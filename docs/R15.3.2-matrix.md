## 5. Brechas §26 (F7 — cerradas en este cierre)

- **Brecha funcional real (única)**: `resetPassword` / `verifyEmail` consumían el token y luego actualizaban el usuario en pasos separados — si el update fallaba, el token quedaba quemado sin efecto (o el efecto quedaba sin consumo atómico).
- **Fix**: ambos flujos corren dentro de `uow.withTransaction`; `consume(tokenId, tx)` + `update(user, tx)` comparten la misma sesión (`reset-password.ts:56-73`, `verify-email.ts:48-65`); el hash (bcrypt, lento) se calcula FUERA de la tx. Puertos: `AuthTokenStore.consume(tokenId, tx?)` (`ports.ts:304`) y `UserRepository.update(user, tx?)`.
- **Test de integración**: `auth-atomicity.test.ts` — **2/2 PASS**: (1) rollback REAL (fallo inyectado en el update → el token sigue `used:false` y `passwordHash` intacto); (2) happy path (consume + update commitean juntos).
- **Brecha documental B1**: la matriz PRE (título "estado PRE-corrección", 16 filas declaradas en FAIL) quedó superada por esta versión POST.
